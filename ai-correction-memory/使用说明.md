# AmendLoop · 知改 · 0.2.2

带机制流程图的项目介绍与快速开始见 [README.md](README.md)。英文名为 AmendLoop，中文名「知改」，建议 GitHub 仓库名为 `amendloop`；现有安装标识与调用名仍为 `ai-correction-memory`。

把你对 AI 的纠正整理成有适用范围的规则，后续回答前读取和检查。核心代码在本机运行，不调用第二个模型，不需要 API 密钥；理解你的纠正和检查回答语义仍由当前聊天模型完成。

## 在 Codex 安装

需要可用的 Python 3.10 或更高版本。在解压后的本目录运行：

```powershell
python install.py
```

安装位置为 `CODEX_HOME/skills/ai-correction-memory`，未设置 CODEX_HOME 时使用 `~/.codex/skills/ai-correction-memory`。受限环境必须先取得目标目录的写入权限；安装程序不会绕过权限。

已有 0.1 版或带完整性清单的版本，使用：

```powershell
python install.py --upgrade --check-only
python install.py --upgrade
```

升级前会核对旧版受管理文件是否被改过，发现个人修改就停止。新文件与个人文件冲突时也停止。升级前备份旧程序，写入中途失败会回滚已替换文件，额外的个人文件不动。首次打开旧数据库时自动备份并迁移到 v2；安装程序本身不修改数据库。升级期间请关闭正在使用该技能的其他进程，避免同时加载一半新一半旧的文件。

重新打开会话，让宿主重新发现技能，然后输入：

> 使用 $ai-correction-memory。接下来按我的纠正更新理解，回答前检查有没有重复误解。

之后照常对话即可。用户不必写 JSON。技能支持自动选择，但是否被自动选中取决于宿主；显式调用最可靠。安装不会自动修改其他技能、全局指令、宿主钩子或 MCP 配置，也不会截获所有聊天。

如果 `python` 是失效的 WindowsApps 别名，可改用已安装 Python 的完整路径。Codex 自带运行时的本机常见位置是 `~/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe`；位置以你的安装为准。

## 平时怎么说

| 你说的话 | 技能应做的事 |
|---|---|
| “不是这个意思，我要先看到结论” | 当场纠正，并记录为本会话规则 |
| “以后都先给我结论，记住这个” | 保存跨会话规则，并留下你的授权原句 |
| “只在这个项目里按这个格式” | 保存项目规则，仅对指定项目根目录适用 |
| “这次先讲过程” | 仅当前任务覆盖同一偏好，交付前结束例外，下一任务恢复 |
| “你记住了什么？” | 列出规则及适用范围 |
| “撤销刚才对那条规则的修改” | 恢复上一个版本 |
| “再撤销一次 / 重做” | 沿历史继续后退 / 前进，不再在两个版本之间来回切换 |
| “这条要求只用到12月1日” | 设置明确时区的有效期，到期不再读取 |
| “刚才哪些规则实际生效了？” | 展示读取、覆盖、排除和自评阶段的记录 |
| “清理重复规则” | 找出词面相似候选；仅对确认的完全相同要求合并，并保留来源 |
| “把我的规则备份 / 导出” | 创建数据库快照或可迁移的JSON规则文件 |
| “忘掉先给结论这条规则” | 删除指定规则及其数据库内历史 |

会话规则也会落盘，它们只是不会被其他会话取用；可要求“清除此会话的纠正规则”。长期规则由你明确要求保存，普通纠正不会自动推广到所有任务。

任务级规则同时绑定会话与任务ID；仅有相同名字而会话不同也不会串用。技能会在交付前关闭当前任务；关闭状态持久保存，不靠“模型记得取消”来恢复偏好。宿主仍须调用结束工具；如果技能没有被执行，工具不能自行识别任务何时结束。

## 它实际检查什么

每条规则包含目标、已拒绝的替代办法、验收问题和一小段来源原话。调用技能后，当前模型在回答前比较这些条件；必要时修正草稿。

例如你拒绝了抽帧代替连续观看，验收问题就是“有没有把同一个替代方案换个名称再次推荐？”而不是机械禁止出现“抽帧”两个字。程序能做字面扫描并给出检查表；它不能独立验证语义，也不能保证模型永不犯错。不会把一个空的扫描结果标成“语义审核通过”。

每次读取生成生效记录。记录区分“已读取”“已扫描草稿”“模型自报满足”“需要修改”“不确定”，不会把“调用过工具”混成“已经检查通过”。模型要为每条读取的规则提交状态与简短依据；漏项、重复项和旧版本记录会被拒绝。不适用的场景分支要说明原因。

同一个偏好可分别保存写作版与编程版；不指定领域时两者都返回，由当前任务选择适用分支。每个领域内依次由任务、会话、项目、全局覆盖；跨领域规则不会把彼此悄悄隐藏。不同 key 但语义冲突的要求仍需当前模型判断，程序不冒充语义裁判。

## 已有开源能力与新开发部分

- SQLite / FTS5：通过 Python 自带的 sqlite3 实际承担存储、事务和检索。中文补充本地单字与双字索引；没有语义向量或外部嵌入模型。SQLite 未启用 FTS5 时回退到本地词项扫描。来源：<https://www.sqlite.org/fts5.html>，公共领域：<https://www.sqlite.org/copyright.html>。
- 官方 MCP Python SDK：可选 stdio 接口，供支持 MCP 的宿主调用同一规则库。来源：<https://github.com/modelcontextprotocol/python-sdk>，MIT 许可证。该依赖通过包管理器安装，本包不复制其源代码。
- 本包新增：纠正结构、任务/会话/项目/全局范围、分场景覆盖、有效期、版本冲突检测、多步撤销重做、生效记录、重复规则整理、备份恢复、导入导出、升级保护和可重复行为测试。

没有集成 Mem0 或 Supermemory，也不声称把它们的代码包含在本包内。本版优先实现无需外部模型、无需服务账户的本地流程。

## 可选 MCP 接入

普通技能用法无需此步骤。只有需要 MCP 工具接入其他宿主时才安装 SDK：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-mcp.txt
```

这里有意固定为官方 v1 维护线的 `mcp==1.30.0`，不是 v2 API。配置宿主时，command 填该虚拟环境 Python 的绝对路径，args 填 `scripts/mcp_server.py` 的绝对路径，例如：

```json
{
  "mcpServers": {
    "ai-correction-memory": {
      "command": "C:/your/path/ai-correction-memory/.venv/Scripts/python.exe",
      "args": ["C:/your/path/ai-correction-memory/scripts/mcp_server.py"],
      "env": {"AI_CORRECTION_MEMORY_DIR": "C:/your/path/correction-data"}
    }
  }
}
```

这是通用 MCP JSON 示例；Codex 等宿主可能采用其他配置格式，请使用宿主的 MCP 设置入口填写 command/args/env，勿直接覆盖已有配置。MCP 仅暴露工具，不会强制每次回答自动调用。

## 数据位置与迁移

Windows 默认 `%USERPROFILE%/AppData/Local/ai-correction-memory`；有意不跟随宿主每次可能变化的沙箱或应用包 LOCALAPPDATA，实际写入仍受宿主权限限制。Linux/macOS 默认 `$XDG_DATA_HOME/ai-correction-memory` 或 `~/.local/share/ai-correction-memory`。可设置 `AI_CORRECTION_MEMORY_DIR` 指向自选目录，包括主动选择重定向位置。使用 CLI 的 `--data-dir` 只影响该次命令；MCP 要用同一环境变量才能共享。

规则和生效记录保存在本地未加密的 SQLite 数据库中。生效记录包含读取的规则快照及模型提供的简短检查依据，不保存完整草稿（只存哈希）。应用不向外部服务发送网络请求；MCP的Python异步运行时在Windows受限沙箱下可能需要本地回环权限。把规则取回聊天时，它们会进入当前宿主的模型上下文，因此“本地数据库”不等于“内容绝不进入模型服务”。正常卸载技能不会删除独立的数据目录。

用 `backup` 可以在数据库正常使用时生成一致的 SQLite 快照，无需手工拼 WAL 文件。完整恢复前请停止其他客户端，`restore` 会验证备份并先保留当前数据的安全副本。`export` 默认只导出长期规则，`import` 默认预览，明确应用后才新增，冲突不覆盖。详细命令见 `references/commands.md`。

忘掉规则会删除活动规则、历史和数据库内相关生效记录；已产生的独立备份、导出文件和宿主聊天记录不会随之删除。程序升级备份默认放在数据目录的 `package-backups`，数据库备份在 `backups`。这些备份也可能含旧偏好，需要自行管理保留范围。

## 验证

在目录中运行：

```powershell
python -m unittest discover -s tests -v
python scripts/demo.py
```

核心测试只需标准库；MCP 集成测试在 SDK 未安装时明确跳过。演示使用临时数据库，不会写入真实偏好。测试通过说明所列存储和接口行为正确，不代表已经证明对所有任务都能减少模型误解。

独立模拟对话对照评测的输入、原始输出和评分放在 `evals/`。这是小样本工程评估，不等于真实用户长期实验；效果报告区分同一聊天已有纠正与新聊天读取长期规则，避免把模型本来就能做到的能力误算成技能收益。

## 使用边界

这是能安装和运行的技能原型，不是对所有 AI 网站的通用注入器。适用于允许本地技能或 MCP/命令行工具的宿主；普通网页版是否能使用取决于其开放接口。它不改变模型权重、上下文上限或视觉输入能力，也不提供连续视频观看。
