# 对照评测方法

这是模拟对话的小样本工程评估，不是真实用户长期实验，也不是模型排名。

## 输入与隔离

`cases.json` 有12个独立场景，覆盖写作、学习、办公和编程，每类3个。
其中4个保留同一聊天中已经出现的纠正；8个模拟用户开启新聊天后，
从长期记忆取回曾明确保存的偏好。对照组与技能组使用同样的当前用户消息。
新聊天的对照组没有旧偏好，因此不符合旧偏好不代表它答错当前问题。

对照与技能执行分别由独立代理完成，无父聊天历史，不互看输入、输出或评分标准。
没有给执行代理指定不同模型；使用当前宿主继承的模型与默认配置。
每个执行代理处理各自12个隔离样本，没有多次采样或随机种子控制。

技能组读取交付的SKILL.md，实际通过CLI调用prepare、assess、finish-task，
只使用预置的临时数据库，不读真实用户偏好。对照组只接收当前聊天的turns。
工具本身没有调用外部模型，独立代理仅用于这次开发评估。

## 评分

完成两组输出后，按预先写下的case criterion建立匿名A/B对。
另一独立评审只接收criterion、当前对话和两条匿名答案，不知道组别。
每个答案按 `met` / `violated` / `uncertain` 评分，并给可核对的依据。
这些标准是用户偏好是否得到保留，不能用来推导普遍任务正确率。

`score_eval.py`根据解盲映射与评审输出计算：

- 总体及同聊天/新聊天的偏好满足数。
- 技能组退步或不确定的案例。
- 各领域结果和原始评分依据。

“需要再次纠正的代理指标”只是violated数量，不是用户真实又纠正了几次。
不把小样本结果宣传成重复误解下降百分比，也不把检查依据当作独立验证。

## 耗时

`engine-metrics.json`是本地规则准备耗时，120次调用，每个案例只有1条规则。
它排除了模型推理、工具调度和网络，不代表端到端对话延迟。
代理执行耗时若记录，只作这次运行说明，不作不同组速度比较，因为工具
调用、并发、排队和处理顺序不受控。

## 复现

在同一宿主中开独立评估会话：一组只传当前turns，一组使用本技能并在隔离
目录预置saved_correction。两组均输出case ID和answer。请勿把criteria传给生成答案的会话。
另开评审会话，用固定criterion对匿名答案评分，保留不确定项。
原始答案放入baseline-output.json与treatment-output.json；结果文件
blind-grades.json需为数组，每项有id、A/B对象，各含status和evidence。
`blind-map.json`记录每个ID下A/B对应baseline或treatment。

```text
python evals/score_eval.py --directory evals
```

有限制或结果未完成时，应明确标注，不用测试夹具或手写答案冒充独立模型实验。
